## Specs

- S1: "This repo is meant to hold all the skills used in my company. It currently has skills we own but I also want it to hold third party skills like the mentioned in ~/dotfiles/config/ai/skills". Keep owned skills intact. Add a tracked approved-source catalog, seeded from the referenced dotfiles list recovered from Git history. Record source, exact approved revision, skill identities, and license provenance. Report unavailable sources rather than inventing pins or licenses.
- S2: "I want to be able to run a cli command in any new repo, check all the skills I want installed in that project and get them installed and commited to the repo." Implement a project-local checkbox selection command, an explicit noninteractive selection path, recorded selections, installed files, native lockfile, and an explicit scoped commit option. Preserve unrelated files and staged changes. Do not overwrite locally modified installed skills silently. Validate cancellation, invalid input, installation failure, and repeat installation through public command tests in isolated repositories.
- S3: "ok I like the approach, use react for the TUI/CLI if needed. Implement using luna workers". Use TypeScript with React Ink for interactive selection. Delegate independent bounded implementation units to `openai/gpt-6-luna`. Reuse a pinned published `skills` CLI release rather than reimplementing its agent installation behavior. Verify exact revision installation against that release. Document local use before publication; do not imply the unpublished package already exists remotely.
- S4: "Keep a copy of the third party skills and update them monthly using a cron github action to sync from their repos? or can we keep just a list of skills and install from source?". Implement the accepted catalog-first recommendation: install from approved upstream revisions; retain installed files in each consuming project. A monthly workflow proposes catalog revision changes in a reviewable PR, never silently merges or updates consuming projects. Retain third-party license provenance. Do not publish packages, push branches, or create remote PRs during this implementation.
